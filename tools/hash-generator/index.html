Detailed explanation

A hash function takes any input of any size and produces a fixed-length fingerprint: 64 characters for SHA-256, for example. Its core property is that changing a single input character completely scrambles the output — the essence of integrity checking.

The most common practical use is verifying downloads: the official site publishes the file's hash, you hash your downloaded copy and compare — a match means the file was not tampered with in transit.

Why not MD5 anymore? Researchers proved years ago that two different files can share one MD5 hash (a collision), so it survives only for legacy compatibility, while SHA-256 remains a sound standard today.

Worth clarifying: hashing is not encryption — the original text cannot be recovered from the hash by design, which is exactly why storing password hashes (with salt) is correct practice while storing raw passwords is a disaster.

The tool computes all algorithms locally through your browser's Web Crypto API — the same library browsers use for HTTPS, so accuracy is guaranteed and speed instant.

FAQ

Can I reverse a hash to get the original text?

No, the design is one-way; so-called rainbow tables are just precomputed guesses for common inputs, not real reversal.

Which algorithm should I choose?

SHA-256 is the sound default for any modern use; MD5 only when a legacy tool specifically demands it.

Are hashes identical across systems?

Yes, hash algorithms are universal standards — the same input yields the same hash on any machine.
