Detailed explanation

A UUID is a universal 128-bit identifier written as 36 characters in the 8-4-4-4-12 pattern. The popular v4 version is random: the chance of two v4 IDs colliding is so tiny that generating a billion per second for a hundred years would practically never collide.

Why not settle for sequential 1, 2, 3? Because distributed systems cannot agree on a shared counter; a random ID can be generated on any server, device or branch without coordinating with anyone and still stay unique — the foundation of modern distributed database design.

Daily uses are vast: foreign keys in tables, API request IDs, collision-free filenames, session identifiers and test fixtures.

Older versions exist, like v1 built from the network's physical address and time, but they lost popularity for leaking information about the generating source, while v4 is fully neutral.

The tool uses the cryptographically approved crypto.getRandomValues in your browser — not Math.random, which can repeat — a true entropy source designed for security systems.

FAQ

Can UUID v4 repeat?

Statistically yes, but practically impossible: collision odds are far below your odds of being hit by a meteorite today.

What is the difference between v4 and v1?

v1 is time and network-address based (it can reveal its source); v4 is fully random and more privacy-friendly.

Is UUID suitable as a database primary key?

Yes, especially in distributed systems — just note it is larger than sequential integers, slightly affecting index performance.
