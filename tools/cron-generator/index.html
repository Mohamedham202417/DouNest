Build and understand cron expressions.

How to use

  1. Set the five fields: minute, hour, day of month, month, day of week.
  2. Or use quick buttons for common schedules: hourly, daily, weekly.
  3. Watch the expression form in the output field as you configure.
  4. Read the generated human description to confirm the pattern means what you intend.
  5. Copy the expression into crontab or your project's scheduler settings.

Detailed explanation

The cron format is a half-century industrial standard for running tasks periodically: nightly database backups, hourly report refreshes, weekly temp-file cleanup — every Linux server lives on this five-field syntax.

Why a generator instead of hand-writing? Because cron defies human intuition: is day of week 0 or 7? Does a star in day-of-month combined with day-of-week mean OR, not AND? Professionals trip on these traps, and the generator sets them precisely.

The generated human description is the real safety feature: «every Monday and Tuesday at 9:00» — read it and correct it before copying, because a scheduling error means a backup that never ran or a report that never arrived.

Special fields like */5 (every five minutes), ranges (1-5) and lists (1,15) are supported through buttons — no need to memorize cryptic symbols.

Popular ready recipes: 0 3 * * * (backup at 3 AM), */15 * * * * (health check every quarter hour), 0 0 1 * * (monthly report on the 1st).

FAQ

What does a star in a field mean?

It means every value of that field — a star in hours means every hour within the other fields' values.

Does the server follow my timezone?

cron follows the server's default timezone — check it or set TZ in crontab to avoid timezone surprises.

What is the difference between cron and systemd timers?

Similar time syntax; systemd offers richer logs and smart retries, but cron is simpler and more universally supported.
