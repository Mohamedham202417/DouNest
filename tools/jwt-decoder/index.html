How to use

  1. Paste the full JWT (three dot-separated parts) into the input.
  2. Press Decode to display the header and payload as two separate tables.
  3. Check the exp and iat fields for expiry and issue times.
  4. Inspect the algorithm declared in the header (HS256, RS256, etc.).
  5. Watch for the red expiry notice if the token has already expired.

Detailed explanation

A JWT is the most popular authentication standard in modern APIs: three parts — a header describing the algorithm, a payload carrying claims (who the user is, roles, permissions), and a signature guaranteeing tamper-proofing. All three are Base64-encoded, not encrypted, which is why a decoder reads them so easily.

The tool reveals a truth many miss: anyone can read the token's contents; the real protection is the signature alone, which prevents forgery, not reading. So never place sensitive data inside the payload.

Checking exp and iat manually requires annoying timestamp math — the tool converts them into human dates and tells you whether the token is still valid right now.

Developers use it daily to debug authentication: why was the token rejected? Did it really expire, or is the server rejecting the signature? Are the claims the server sent the ones you expected?

An honest security note: the tool works locally and only displays content, but as a general habit avoid pasting live production tokens — even though local-only reading is theoretically safe, transparency is best practice for security tooling.

FAQ

Can the tool verify the signature?

No — verification needs the secret key owned by the server; the tool is for inspection and analysis only.

Why do I see strange characters in the payload?

Usually the token is truncated or has quotes from copying — paste the three parts exactly, separated by two dots.

Is a JWT safe if I paste it here?

Processing is 100% local, but as professional hygiene never paste live production tokens into any online tool.
