How to use

  1. Paste the URL or text that needs encoding into the input.
  2. Choose Encode to convert special characters into safe %XX form.
  3. Or choose Decode to read a URL cluttered with percent signs.
  4. Press Run and copy the result directly.
  5. Use the toggle button to flip between modes quickly while working.

Detailed explanation

URLs are designed around a very small whitelist of allowed characters; anything outside it — a space, an ampersand, Arabic text — must be represented as percent-encoding %XX so it does not break the URL structure or get misread as part of it.

The most dangerous confusion involves & and = inside parameter values: sending a value containing & unencoded makes the server read it as a new parameter separator, losing your data or worse. That is why encodeURIComponent and encodeURI differ fundamentally, and the tool offers both modes.

Decoding matters just as much: many links shared across networks arrive cluttered with %D8%AF and friends, and decoding reveals the readable original text.

Search links, campaign tracking and API endpoints all travel this path; understanding encoding saves you hours of debugging vague 400 Bad Request errors.

As always at DouNest, all processing is local: your private or internal-system URLs never leave your browser.

FAQ

What is the difference between encodeURI and encodeURIComponent?

The first preserves full URL structure (/, &, ?, :), while the second encodes everything including separators — use it for parameter values themselves.

Why does Arabic appear as strange codes in URLs?

Because URLs travel as UTF-8 then percent-encoding; decoding reveals the original text.

Does encoding change the actual link?

No — the server decodes automatically and reaches the same value; encoding is purely for transport.
